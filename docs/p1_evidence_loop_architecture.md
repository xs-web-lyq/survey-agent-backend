# P1-B 研究问题驱动证据闭环

## 目标

把“证据充分”的判定单位从章节 chunk 总量改为研究问题。Research Brief 是上游研究契约，大纲、检索、检查点、证据矩阵和写作必须使用同一组问题。

## 主链路

```text
已确认 Research Brief
  -> 全局研究问题
  -> 绑定到大纲章节 research_questions
  -> 每个问题执行基础检索
  -> 评估问题覆盖与独立来源
  -> 对未覆盖缺口执行有界补证
  -> 达标 / 平台期 / 预算耗尽
  -> 持久化检查点与停止原因
  -> 证据约束写作并公开证据矩阵
```

## 核心不变量

1. Brief 中每个已确认研究问题必须原样进入至少一个章节。
2. 单个问题至少需要 2 个证据块和 2 个独立来源。
3. 章节还需要 2~3 个全局独立来源，问题全部覆盖且来源门槛满足才算充分。
4. chunk 总量只控制写作上下文容量，不能改变覆盖判定。
5. 未达标时允许写作，但必须保留研究空白，不能用无依据内容补齐。
6. 自动补证是有界的：每个问题一轮基础检索，再增加最多 3 轮缺口检索，总轮数不超过 8。

## 补证策略

缺口轮按当前不足确定查询策略，并在后续轮次轮换：

- `source_diversity`：寻找对比研究、工业试验、多钢种或其他独立来源。
- `quantitative_evidence`：寻找定量结果、参数范围、实验数据和统计结果。
- `mechanism_evidence`：寻找作用机制、因果关系和模型验证。

## 停止条件

- `coverage_satisfied`：所有研究问题和章节独立来源门槛均满足。
- `plateau`：完成基础检索后，连续两轮没有新增问题证据。
- `budget_exhausted`：达到本节自动检索预算。
- `manual_supplement_exhausted`：用户定向补证结束后仍存在缺口。

停止原因和逐轮历史保存在章节证据检查点中，并投影到前端证据矩阵。服务重启后可以恢复同一状态，不依赖进程内事件。

## 持久化边界

私有检查点保存完整 chunk 内容、查询和逐轮历史，供恢复写作使用；公开证据矩阵只暴露来源、分数、摘要、覆盖缺口与停止原因，避免前端承担判定逻辑。

检查点与公开矩阵使用独立版本号：P1-B 保持检查点 v1 以恢复历史任务，将公开矩阵升级为 v2，使旧缓存自动重建而不丢失检索证据。

## 代码位置

- `backend/agent/evidence_coverage.py`：问题绑定、覆盖判定、预算和缺口查询。
- `backend/agent/evidence_store.py`：检查点与公开矩阵。
- `backend/agent/phases.py`：多轮检索状态机与恢复。
- `backend/agent/prompts.py`：大纲问题契约。
- `frontend/src/components/EvidenceMatrix.tsx`：覆盖缺口与停止原因展示。
